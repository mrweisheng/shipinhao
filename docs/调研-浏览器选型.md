# 视频号浏览器自动化 · 选型调研

记录时间：2026-10-24
环境：Windows / Chrome 155.0.8059.80 / Edge 156 / Node v? / playwright-core 1.60.0（随 openclaw 附带）
目标：OpenCode 驱动有头浏览器打开视频号助手，检查登录 → 提醒人工扫码 → 抓取视频评论

---

## 一、需求约束

1. **必须有头**：窗口可见，方便人工观察任务执行。
2. **不能一眼看出是机器**：不能出现 `navigator.webdriver=true`、不能有顶部"Chrome 正受到自动测试软件的控制"提示条。
3. **不占用鼠标键盘**：任务运行时，用户仍能正常使用电脑。
4. **登录必须成功**：历史经验是「扫码成功但页面不跳转」。
5. 所有产出、记录都在本目录。

---

## 二、候选方案实测

### 2.1 启动方式对照实验

同一台机器、同一 Chrome 155，只改「谁启动浏览器」：

| 启动方式 | `navigator.webdriver` | 自动化提示条 | `navigator.plugins` | UA |
|---|---|---|---|---|
| 手动启动 Chrome + `connectOverCDP` | **false** | 无 | 5 | 正常（无 HeadlessChrome） |
| Playwright 默认 `launch({channel:'chrome'})` | **true** | **有** | 5 | 正常 |

结论：**决定指纹的不是"用哪个库"，而是"谁拉起浏览器进程"。**
只要浏览器是被我们自己手动拉起的（不带 `--enable-automation`），后续用 CDP 挂上去，
`navigator.webdriver` 就是 `false`，提示条也不会出现。

实测脚本：`scripts/probe-fingerprint.js`

### 2.2 MCP 工具对照

| MCP | 版本 | 能否挂已有 Chrome | 关键参数 | 备注 |
|---|---|---|---|---|
| chrome-devtools-mcp | 1.12.0 | ✅ | `--browserUrl http://127.0.0.1:9222` | 有 `--slim` 只暴露 3 个工具，省上下文；Puppeteer 内核 |
| @playwright/mcp | 0.0.83 | ✅ | `--cdp-endpoint <endpoint>` | 工具更偏交互操作；Playwright 内核 |

两者都可挂 CDP，不冲突，可按阶段切换。

### 2.3 反检测：真正的杀手是 CDP 协议泄漏

社区已定位出比 `navigator.webdriver` 更隐蔽的信号 —— **`Runtime.enable` 泄漏**。
Puppeteer / Playwright 为了执行 JS，会对每帧发 `Runtime.enable`，页面里几行 JS 就能探到。
Cloudflare、DataDome 等主流风控都在用这个信号；这解释了「改 UA、改 webdriver 都没用」。

对应方案：
- **Patchright**（Playwright 补丁分支，2026-10-14 仍在跟版，支持 `channel=chrome` 驱动系统 Chrome）
  修补 `Runtime.enable`、`Console.enable`，会移除 `--enable-automation` 并加 `--disable-blink-features=AutomationControlled`。
- **rebrowser-patches**（补丁集，Node 端为主，2024-09 后基本停更）

但注意：**任何挂在 CDP 上的 MCP（含 chrome-devtools-mcp / @playwright/mcp）都会重新引入 Runtime.enable 泄漏**，
因为它们的工具实现依赖 `page.evaluate`。

## 三、网络：本次最可能的真凶

本机挂着代理（进程 `mantouyun-core`），系统级生效：

```
ProxyEnable   = 1
ProxyServer   = 127.0.0.1:7890
ProxyOverride = <local>;127.*;192.168.*;10.*;172.16-31.*     ← 只绕过内网
```

实测：

| 路径 | 出口 IP | 归属 | 视频号登录页 |
|---|---|---|---|
| 直连 | 111.60.73.11 | 中国移动 · 湖北武汉 | 200 / 0.43s |
| 走 7890 | 42.200.231.106 | 香港机房 | 200 / 0.31s |

**系统代理会让视频号请求以香港机房 IP 出网。** 跨境 + 机房 IP 是国内平台风控的高危特征，
「扫码成功但不跳转」很可能源于此，而不是指纹问题。

处置：给自动化专用的 Chrome 加 `--no-proxy-server`，让它**强制直连**，
不依赖 Clash 的分流规则（规则随时可能变，不可控）。

## 四、视频号助手站点结构（实测）

| 事实 | 证据 |
|---|---|
| 登录页 = `https://channels.weixin.qq.com/login.html` | 返回 Vue SPA 壳，加载 `login.18085ae7.js` |
| 后台 = `https://channels.weixin.qq.com/platform/` | 返回 200，由前端 JS 判断登录态 |
| `/platform` → 301 → `/platform/` | curl 实测 |
| 二维码不是静态图 | 由 `login.js` 运行时渲染，静态抓 HTML 拿不到 |
| 移动端 UA 会被踢到 `/mobile/mobile.html` | 页面内联脚本 |
| 后台是 **wujie 微前端 + shadow DOM** | 社区多个 skill 一致反馈：常规 `querySelector` 找不到表单元素，需穿透 `wujie-app` 的 `shadowRoot` |

登录态判据（简单可靠）：**看 SPA 自己跳到哪个 URL**
- 含 `login` → 未登录
- `/platform/home`、`/platform/post/list` 等 → 已登录

## 五、方案定稿

### 核心思路：把「登录」和「自动化」彻底解耦

登录是唯一敏感环节（微信要判断这一下）。既然如此：

> **登录期间，不挂任何自动化协议。用的是一个人手点的、干净的 Chrome。**

检测手段只有两种可能：`webdriver` 类指纹，或 CDP `Runtime.enable`。前者已被干净启动解决；
后者只要**不挂 CDP 客户端**就不存在。而"是否登录成功"这件事，用**纯 HTTP 轮询调试端口**就能判断：

```
GET http://127.0.0.1:9222/json/list
```

这个接口由 Chrome 自己提供，返回当前所有标签页的 URL/标题。
**它不建立 CDP 会话，不触发 Runtime.enable，页面完全无感。**
用它盯 URL 变化，等于在门外看窗户，人已经进屋了却不留脚印。

### 阶段划分

| 阶段 | 做什么 | 自动化介入程度 |
|---|---|---|
| 1 | 干净启动 Chrome，打开登录页 | 无（纯手动浏览） |
| 2 | HTTP 轮询 `/json/list` 判断登录结果 | **零 CDP** |
| 3 | 登录成功后，再挂 MCP 抓评论 | 有 CDP（此时已过风控敏感期） |

### 备选方案（阶段 3 若也被拦）

| 代号 | 方案 | 适用 |
|---|---|---|
| A | 干净 Chrome + `/json/list` 轮询登录，登录后挂 chrome-devtools-mcp | 默认方案 |
| B | 干净 Chrome + 全程挂 chrome-devtools-mcp | 验证 CDP 泄漏在视频号是否真的被检测 |
| C | 干净 Chrome + 全程挂 @playwright/mcp | 同上，换内核 |
| D | Patchright + 系统 Chrome + 有头 | A/B/C 都失败时上重武器 |

### 明确不做

- 不用 `--headless`（要求可见，且 headless 有独立指纹）
- 不让 MCP 自己 launch 浏览器（会产生 `webdriver=true` + 提示条 + 每次新 profile 要重扫码）
- 不改 UA、不注入伪装脚本（改得越多越容易被 `Object.defineProperty` 反向探测）
- 第一版只读评论，不做回复/点赞/发布

## 六、风险与约束

1. **重试次数有限**：每次失败登录都是一次风控记录，不能反复刷。所以按 A→B→C→D 顺序，一次只试一个。
2. **Cookie 寿命**：社区反馈视频号 Cookie 有效期偏短，需定期检查登录态。
3. **抓取频率**：拟人节奏（点击间隔 0.5–2s），首轮只取少量验证。
4. **本机 Chrome 已在运行**（10 个进程），必须用独立 `user-data-dir`，否则 profile 被锁。
5. **Chrome 136+ 限制**：`--remote-debugging-port` 必须搭配非默认 `user-data-dir` 才生效，本方案已满足。
