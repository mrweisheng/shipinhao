# 04 案例库（写作基准，执行必读）

> 定位：**怎么写回复**的唯一基准文件。规则权威顺序：**00 纪律 > 04 案例 > 01 语料**。
> 案例库数据在项目根 `data/cases/`（`seed.jsonl` 人工种子 + `cases.jsonl` 自动/新增），
> 用 `scripts\15-case-library.js` 检索；本文件只写"怎么写"的方法与评审，不重复 00/01 的判定与话术。

## 1. 写作四步法（每条回复都走，缺一步视为流程违规）

1. **asked 复述（必填）**：把客户的问题用一句话复述出来。写不出 = 没看懂，停下重读评论，
   不许凭感觉写。
2. **检索案例**：按意图检索 **2 条好案例 + 1 条坏案例**（好案例看怎么答，坏案例看避开什么）：
   ```powershell
   node scripts\15-case-library.js --search "客户原话" --intent car_payment --top 5
   ```
3. **生成 3 个候选**：基于 2 好 1 坏，写出 3 条不同引导/语气的候选文案。
4. **五维评审选 1 + answerOk**：按第 2 节五维清单逐条打分，选最优；
   `answerOk` 必须为 `true`（正文直接回答了 asked），否则重写。

## 2. 五维评审清单（每条回复必过，不合格就重写）

| 维度 | 检查点 | 不合格信号（举例） |
|---|---|---|
| ① 回答准确 | 正文（去掉引导尾巴后）**直接回答了 asked**？是/否问题有**明确答案**（係/唔係/可以/唔可以/有/冇）？ | 绕开问题、答非所问、用「都啱傾」糊弄、没给明确答案 |
| ② 口径合规 | 红线全过：禁词（微信/電話/號碼/聯繫方式…）、不设门槛、**不编价格**、不承诺批核/结果、不带关系词、不暗示行情可变 | 出现「實時行情/睇返/浮動/保證得/搞得掂/老友/朋友」、编造数字 |
| ③ 捧场匹配 | 严格贴合对方内容：**纯捧场不加引导**、是/否先答、有业务意向才引导、纯支持不误判为引战而跳过 | 捧场带引导（「買車點頭像私訊」）、对支持者过度跳过 |
| ④ 形式达标 | 全部繁体、含标点 ≤22 字、至少 1 个表情、相邻不重复、引导路径**只一条**（不叠加两条） | 超字数、无表情、相邻 3 条重复、路径叠加 |
| ⑤ 转化价值 | 业务意向给了**完整一条引导路径**（頭像→簡介→私訊 等）；业务相关但事实未知 → 引私域；不承诺细节 | 无引导、缺路径、硬编事实、该引私域却在评论里说细节 |

## 3. 评审必查（盲评暴露的问题，逐条自查）

1. **纯捧场不加引导**：对方只是支持/表忠，不要立刻「買車點頭像私訊」。
2. **是/否问题先答**：先给「係 / 唔係 / 可以 / 唔可以」，再延伸；不要用「都啱傾」绕开。
3. **不要过度跳过支持**：出现"香港/文明"不等于引战；看主语和意图，纯支持就正常多谢。
4. **业务相关未知**：直接 `呢個私訊我，幫你睇清楚 📩`，不写"確認/唔確定"，也不要问"我帮你确认"。
5. **不设门槛是核准口径**：`唔設門檻` / `學歷唔設限` 可以写；但**不能写**"一定批 / 包批 / 保證得"。
6. **包牌税险**：不说明细，但要先承认问题：`包牌稅險嘅嘢，私訊傾清楚 📩`。
7. **做工证/帮办**：先答「係，可以幫你了解」，不承诺结果。

## 4. 少说少错口径（2026-10-27 引入，借鉴手机端策略）

- **客户未提金额**时，全款/首付类**确认问题只答「係，全款」，不报数字、不延伸分期**（少说少错）。
- `{標價}` 报数字模板**仅在客户明确问价**（C2 场景："几钱 / 咩价 / 而家咩價"）时使用。
- **报标价前必须核对视频标题原文**——画面内嵌金额字卡（缩略图）可能是首期/剧情字卡，
  与标题标价不一致（实测：缩略图"3萬3"，标题原文实为「3萬8的埃尔法」）。

## 5. 案例库运转

- **位置**：`data/cases/seed.jsonl`（人工种子）+ `data/cases/cases.jsonl`（自动/新增）+ `data/cases/novel-queue.jsonl`。
- **检索**：`node scripts\15-case-library.js --search "客户原话" --intent car_payment --top 5`
- **统计**：`node scripts\15-case-library.js --stats`
- **自动入库**：`13` 发送成功后自动写一条 `unreviewed` 候选；相似度低于阈值的进 `novel-queue.jsonl`。
- **`unreviewed` 不算好例子**：只有 `--promote` 后才是 good，`--reject` 标 bad。
- **覆盖测试**：`node scripts\17-novelty-scan.js`（先 `node scripts\16-build-eval-set.js --n 100`）。
- **工作流**：先判意图 → 按意图检索 2 好 1 坏 → 生成 3 候选 → 五维评审选 1 → 填 plan。

## 6. 与 00/01/SKILL 的分工

- 00 纪律管"**回不回**"（分类、红线、量级）；04 管"**怎么写**"；01 提供语料与变体。
- 04 不重复 00 的分类判定，也不重复 01 的话术原文；需要话术时回 01 取，需要判定时回 00 查。
