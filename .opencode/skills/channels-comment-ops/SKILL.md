# 视频号评论区维护（本项目专用）

> 事实口径以 `业务事实.md` 为准；红线与判断规则以本文件第 2、5 节为准；
> 生成时**优先检索案例库** `data/cases/`（见第 8 节），`模板池.md` 只提供引导尾巴与兜底候选；
> 页面结构与选择器看 `页面结构与操作点.md`；实测数据看 `docs/试验记录.md`。
>
> 旧的 `视频号评论区维护\references\`（话术库 / 规则总纲 / 执行记录）已废弃并在磁盘上不存在，
> 不要再引用；执行记录写在根目录 `执行记录.md`。

## 0. 核心分工：模型判断，脚本执行

| 层 | 谁做 | 做什么 |
|---|---|---|
| 语义层 | **模型（你）** | 读完整句，判断回不回、回什么、跳过理由 |
| 机械层 | 脚本 | 读评论、校验禁词/长度/表情、发送、三信号核验、点赞、记录 |

**明确禁止**：

- ❌ 用关键词表 / 正则决定业务分类（「打工」「高才」「白色」这类）。
  预置关键词只能覆盖想到的说法，换账号、换业务、换口语就漏，还会误判。
- ❌ 为了某条视频、某个账号写死规则。脚本里没有账号名、视频标题、业务关键词。
- ✅ 规则只写在 `业务事实.md` + 本文件 + 案例库 `data/cases/` 里；换业务/换号只改这些，不改脚本。
- ✅ 脚本里唯一的词表是**安全兜底**：禁词、长度、表情。
- ✅ 业务事实以 `业务事实.md` 为准；业务相关但事实未列明 → `呢個要睇清楚先答到你，點頭像👤搵我 📩`，不写“確認/唔確定”，也不许用“全款/有/冇事故/搞得掂”填空。
- ✅ 视频标题只作背景（车型 / 口岸 / 业务线 / 标价），**不用来判断评论该不该回**。
  方言、看不懂的标题很正常；评论本身是正向业务咨询（学历 / 年龄 / 费用 / 门路 / 身份 / 移民 / 工作）就必须回。

作者身份是唯一可配置项：默认三个号（`明哥揀粤港车` / `明哥揾粤港车` / `明哥粤港车`），
可用 `--author "号A,号B"` 或环境变量 `AUTHOR_NAMES` 覆盖；「作者」badge 也算。

## 1. 前置检查（每次任务开头）

> 本节的命令按当前分支的操作手册执行（`main`：`操作手册.md`；`doubao-port`：《豆包内置浏览器操作手册.md》）。
> **判断规则、话术、配额、核验判据与本文件其余部分，两分支完全一致。**

**同一时刻只可能有一个账号在线。** 每次开始前先确认「现在是谁」，再动手：

```powershell
node scripts\01-launch-chrome.js          # 没启动就先启动（跨平台）
node scripts\26-whoami.js                 # 打印当前账号名
node scripts\26-whoami.js --expect 明哥揾粤港车   # 不一致则退出码 3，此时什么都不做
```

确认账号后，再检查登录与页面：

```powershell
node scripts\07-read-video.js --nth 1 --json .\data\login-check.json
```

- 退出码 2 = 需要扫码：让用户扫码，不要自己重开浏览器。
- 退出码 3 = 浏览器/标签页不可用：提示跑 `scripts\01-launch-chrome.js`。
- 必须是有头 Chrome、CDP 9222、无 `webdriver`、直连（`--no-proxy-server`）。

**页面/路径漂移是常态，脚本负责自适应，不再靠页面尾部猜文字：**

- 账号名读页头 `.account-info .name`（任何后台页都在）；选择器失效时依次退到
  「账号卡片结构启发」→「已登记账号名反查」，**找到即写回 `data/ui-map.json`**。
- 进评论页**URL 直达优先**（`ui-map.json` 的 `commentPageUrl`），失败才走「互动管理 → 评论」；
  哪条路走通、真实 URL 是多少，自动写回注册表。
- 不确定当前在哪一页：`node scripts\26-whoami.js --nav`（自动跳到评论页再确认）。
- **发现新路径 / 新选择器后，人工复核并同步 `页面结构与操作点.md`**（路径、选择器、实测日期），
  否则下次改版时文档会反过来误导。

## 2. 硬规则（违反就不发）

| 规则 | 说明 |
|---|---|
| 只回一次 | 线程里已有作者回复（三个号 + 「作者」badge）→ 永远跳过，用户追问也不回 |
| 不承诺 | 问「还在不在」→「有」；问全款/分期 → **全款可以、分期都可以**（首付/月供/利率不口头报）；问价（已标价）→ 报标题固定价 |
| 不编价格 | 视频未标价（如两地牌）→ 不写数字，用指路口径：`{對象}明細，點頭像👤搵明哥`（无对象 → `明細可以點頭像👤搵明哥`）；轮换 明細/詳情/細節/內容 |
| 不还价 | 「太贵/能不能便宜」→ 不接价、不说可谈 |
| 涉法不接 | 假结婚 / 蛇仔 / 偷渡 / 中介抽佣 / 走捷径绕审批 → 永久跳过，不回、不解释、不辩、不点赞 |
| 公开区不递联系方式 | 禁：微信、VX、wechat、電話、手機、加我、二維碼、號碼、聯繫方式、聯絡方式、唔方便喺度講、私下講。「私訊」不在禁词表，但属**受限词**（配额见 §5.1）；简体「私信」永久禁用；`DM` 不用 |
| 引导照用 | 頭像 / 簡介 / PM / 置頂 / 主頁 / 私訊（受限，见 §5.1）；变体尽量丰富，相邻不重复 |
| 路径 | 一条回复只走一条路径（头像→简介→PM / 头像→简介→私讯 / 私讯 / PM / 置顶），不叠加两条 |
| 文案 | 全部繁体、≤22 字、至少 1 个表情、相邻不重复、7 天内不重复同一句 |
| 点赞=已回复 | 回复核验成功后点赞，但**先查红灰再点**：已赞（红 #FA5151）不点，未赞（灰 rgba(0,0,0,.55)）才点；跳过类永不点赞 |
| 不删不改 | 不删评论、不动置顶、不重复补发被吞的回复（登记即可） |

## 3. 标准流程（模型在环）

### ⓿ 先确定今天该处理哪几条（不碰浏览器）

```powershell
node scripts\25-open-items.js --account mingge-yg --max-video-age 45
```

- 读本地存储（`data/accounts/<账号>/`），不抓浏览器、不发请求
- **视频发布超 45 天的整条排除**，并注明排除了多少
- 排除 `state.jsonl` 里已判 `skip` 的，只列「待处理」
- 输出每条的「声明 / 未回 / 已判 skip / 待处理」，按待处理数排序
- 可选：`--days 14` 只看近两周评论；`--growth` 只看评论数增长的视频

> **不要用「前 N 条视频」当入口。** 序号会随新视频右移，而且第 N 条以后的新评论永远扫不到。
> 2026-10-28 实测：按前 26 条扫，漏掉 4 条视频的新评论，其中 2 条是真实询单（问上牌）。
> 25 列的是**本地已知**的待处理；是否真有新评论，以 §3.5 铁律三的时间增量判定为准（快照会滞后）。

### ① 生成待判断清单

```powershell
node scripts\12-prepare-plan.js --nth 5
# 产出：data\reply\plan-nth5.json（action 全部为 null）
# 同时打印一张表：序号 / 昵称 / 时间 / 原文
```

几百条也没问题：清单一次生成，模型分批判断，最后合并成一份 plan。

### ② 模型逐条判断（这一步不能交给关键词）

**先看视频类型，再判单条。** 观点类视频的评论量极大且几乎全是争论，逐条回既无收益又有引战风险：

| 视频类型 | 怎么认 | 处理 |
|---|---|---|
| 业务类 | 标题/画面指向具体车、牌、口岸、移民业务 | 逐条判，业务咨询必回 |
| 观点类 | 标题是观点句（讲道理、比内地香港、谈人生） | **只回业务意图 + 带文字捧场**；争论、唱衰、地域对比整批 `skip`，不追求清零 |
| 生活类 | 家庭、日常、情感 | 只回业务意图和直接向博主提问的 |

> 判完在 plan 里记 `videoType`，方便复盘「这条视频到底该回多少」。观点类视频的待回数偏高是正常的，不要为了清零去回争论。

对每条评论按顺序问四个问题，命中就停：

0. **视频发布超过 45 天 → 整条视频不做维护**（先判断，再进下面的逐条）。
   理由：45 天前的车大概率已售，现在回「有，喺度」是假话；老视频的存量大、收益低。
   超过 45 天的评论**不判、不回、不点赞**，在 `videos.jsonl` 里标 `outOfWindow`，不用再扫。

1. **作者回过没有？**（`authorReplied=true` 的已被 prepare 排除，不用再判）
2. **是不是红线？** 涉政、内地与香港对比、地域蔑称、人身攻击/骗子指控、涉法话题（假结婚 / 蛇仔 / 偷渡 / 中介抽佣 / 走捷径）、纯嘲讽、唱衰 → `skip`
3. **有没有业务意向？** 问价、问途径、问在不在、问全款、求联系、点名互动 → `reply`
4. **普通互动：先看视频类型，再看量级**（**类型优先**，不要用评论总数压过类型）
   - **观点类**：只回 **业务意图 + 带文字捧场**；纯表情、玩笑调侃、负面/唱衰、地域对比 → `skip`。
     **不看评论总数**——观点视频一爆就几百条，按总量判会让同一条视频前后标准不一致
     （2026-10-28 实测：同一条视频昨天 3 条「全回」、今天 27 条「挑着回」）。
   - **业务类**：业务咨询必回；其余带文字的有效互动可回；纯表情、纯短评 → `skip`
   - **生活类**：业务意图和向博主直接提问必回；评论 ≤20 时连纯表情一起回
   - **「文字捧场」的定义**：有文字且是正向表达（`讲得對` / `講到有道` / `加油` / `明哥` / `教導有方`）
     → **算有效互动，回**。它不是「中性短评」，两者不能混
   - **「中性短评」只指**：无正向也无负面的事实陈述（如「我今天也去了」），此类 `skip`
   - 拿不准 → `skip`（宁可漏回，不要乱回）

然后填 plan：

```json
{
  "index": 12,
  "name": "健文",
  "content": "订购一台白色埃尔法，怎样联系提车",
  "kw": "订购一台白色",
  "asked": "客户在问：白色有没有现车、怎么联系？",
  "action": "reply",
  "text": "白色有得傾；點頭像👤，PM 我 📩",
  "answerOk": true,
  "category": "car_stock",
  "reason": "问白色现车 + 怎么联系 → 报「有」+ 一条完整引导；不编价格"
}
```

- `asked`: **必填**，把客户的问题用一句话复述出来；写不出说明没看懂。
- `answerOk`: **必填 true**，确认正文（去掉引导尾巴后）直接回答了 `asked`；是/否问题必须有明确答案。
- `action`: `reply` / `skip`
- `text`: 仅 reply 需要
- `category`: 自由标签（用于复盘统计，不参与脚本判断）
- `reason`: 判断依据；skip 必填
- 批级自检：相邻 3 条不重复；引导变体要换；没有禁词；每条都有表情；≤22 字。

### ③ 校验（不碰页面）

```powershell

```

校验：禁词、长度、表情、重复文案、重复条目、缺 text。
退出码 4 = 计划有问题，回去改 plan，不要绕过。

### ④ 试运行（新账号 / 新文案 / 首次跑）

```powershell

```

逐条打开面板、输入、检查按钮，然后按「取消」，**不发送**。

### ⑤ 正式发送

**发送前必须先打开目标视频**：`13` 只核对当前页面，不会自己跳转。

```powershell
node scripts\05-open-video.js --nth 5
node scripts\06-extract-comments.js          # 目标评论在深层时必跑，否则定位「命中 0 条」
```

脚本会：定位 → 输入 → 点「评论」→ 三信号核验 → 立刻点赞 → 记 history + 写 `state.jsonl`
（回复成功记 `reply`；计划里的 `skip` 也在同一批落库，所以不用再手工补 state）。

## 3.5 执行期三条铁律（2026-10-30 定版，两分支共用）

> 这三条与浏览器通道无关（独立 Chrome / 内置浏览器都适用），是**做判断之前的前置动作**。
> 任何一条没做，判出来的 `action` 都不可信。

### 铁律一：先展开，再判「作者已回」

- 折叠线程里的作者回复不在初始 DOM 里；不展开就统计 `authorReplied`，必然误判「未回」→ 重复回复。
- 做法：先滚动到底，把该视频所有折叠线程展开（`.load-more` 内的箭头；转圈中不点），再统一统计。
- 实测（2026-10-28，898 条视频）：22 个折叠线程，其中 4 条深线程（≥3 条回复）藏作者回复，展开后才判为已回。
- 判据：`level1 + level2 === total`，`declared - total ≤ 5`，且无剩余折叠箭头。

### 铁律二：先看红灰，再点赞

- 已赞 = 红色（`svg.fill-like`，`rgb(250,81,81)` / #FA5151，带计数）→ **不点**，再点会变成取消。
- 未赞 = 灰色（`rgba(0,0,0,0.55)`，无计数）→ 才点，点后核验变红 + 计数 +1。
- 点完若变灰 / 计数减少（误取消）→ 立即补回。
- 实测（2026-10-28，香港的机会视频）：已赞 14 条红、未赞 37 条灰；作者已赞的一条被误点在先，变成「取消再重赞」。
- 跳过类永不点赞（点赞 = 已回复标记）。

### 铁律三：按时间增量，不按待处理清单

- 本地快照会滞后（实测：`25-open-items` 待处理 0，浏览器已有 2 条新评论）。
- 增量判据 = 评论时间 > 本地 `latest.json` 里 `comments[].time` 的最大值。
- 指纹用**时间 + 内容**；**昵称不可靠**（评论无唯一 ID，昵称会改：宐妍→用户溢莹）。
- 工具：`node scripts\28-diff-comments.js --local <latest.json> --scan <scan.json>`（纯数据，两分支通用）。
- `25-open-items` 只用于列清单与本地对账；每天开工先拿浏览器实时列表对评论数，找增长的视频优先处理。
- 维护完必须把本次扫描写回 `latest.json`（含本次回复），否则下次基准滞后。

## 4. 动作只有四种

| 动作 | 含义 | 结果 |
|---|---|---|
| 回（纯回应） | 正面事实 + 情绪，不带引导 | 回复 + 点赞 |
| 回（带引导） | 正面事实 + 一条 `GUIDE-*` 路径 | 回复 + 点赞 |
| 策略跳过 | 量级不值当、纯表情、中性、内容讨论 | 不回复、不点赞 |
| 永久跳过 | 作者已回、红线、涉法话题、423 锁定 | 不回复、不点赞、不删 |

策略跳过和永久跳过的动作一样，但记录里必须分开写，否则复盘会误以为漏回。

## 5. 文案怎么写

- **先回答问题，再谈引导**：是/否问题必须有明确答案（可以/唔可以/有/冇/係/唔係）；数量问题没数字就引私讯，不要说“要確認”；事实问题没来源就不下结论。把引导尾巴去掉，剩下的主体必须能独立回答客户。
- **问价 = 指路，不评价价格**：未标价时写 `{對方問的對象}明細，點頭像👤搵明哥`；泛问无对象写 `明細可以點頭像👤搵明哥`。
  轮换词：**明細／詳情／細節／內容**。**不写**「價錢公道／實惠／最抵／明碼實價／一車一價」——自评听着虚，也像每人报不同价。
- **對象取自客戶原話**：蓮塘 → `蓮塘明細…`；30系 → `30系明細…`；包牌 → `包牌明細…`。不加我們未確認的配置／價格。
- **同一视频多个问价**：靠對象詞自然错开；两个都无对象时换句式，别连发同一句。
- **不套用「明細」**：问在不在／地址／时间／车况／能不能上牌，直接答（否则只是换一种清一色）。
- **业务事实以 `业务事实.md` 为准**；业务相关但事实没写清楚的，统一 `呢個要睇清楚先答到你，點頭像👤搵我 📩`，不写“確認/唔確定”。
- **付款**：全款可以、分期也可以；问「能不能分期/首付/月供」→ `可以分期，詳情私訊傾 📩`，首付/月供/利率/期数不口头报。
- **车况**：只说「可以驗車 / 可以試車」；**不承诺**无事故、实表、里数、年份。
- **库存**：问「还有没有/在不在」→ 统一「有，喺度」。
- **营业时间/地址**：朝九晚九（09:00–21:00）；皇后山，导航搜「明哥中港牌」。正常回，不私訊。
- **包牌/包税/包保险**：不说明细，`包咩細節，私訊傾 📩`。
- **高才/优才**：不设门槛，肯定式；**不承诺**批核/时间/结果；不说「搞得掂」。
- **求职/打工**：无招聘信息；模糊承接 + 引私域，不答应、不拒绝、不承诺。
- **高意向/求联系：主体 + `；` + 一条 `GUIDE-*`**。例：
  `白色有得傾；點.頭像👤，PM 我 📩`（默认短 CTA：点头像 + 出口，不写「睇簡介」；私訊见 §5.1 配额）。

### 5.1 引导纪律（2026-10-30 改：顺序 + 滚动配额）

**顺序：直接答 > 頭像（簡介） > PM 我 > 私訊。** 能直接答就绝不带引导。

| 客户问 | 直接答（`CAR-*`，不带引导） |
|---|---|
| 地址 / 几点开门 / 想去看车 | `CAR-VIEW`（8 条，0 条含私訊） |
| 车况 / 年份 / 里数 | `CAR-COND`（8 条，仅 2 条含私訊） |
| 还有没有 / 在不在（现车视频） | `CAR-STOCK`（12 条，0 条含私訊） |
| 卖车 / 收车 / 置换 | `CAR-SELL`（8 条，0 条含私訊） |

只有两种场景才用 `GUIDE-*`：**问价（未标价不能编数字）**、**事实未列明（身份要求 / 退车 / 包税险）**。

> 问价的固定口径：`{對方問的對象}明細，點頭像👤搵明哥`（无对象 → `明細可以點頭像👤搵明哥`）。
> 「明細」只是指路，不是价格声明；轮换 明細／詳情／細節／內容，不评价、不喊口号。

**出口：PM 为主，「私訊」降为受限词，DM 不用。**

| 出口 | 定位 | 写法 |
|---|---|---|
| 直接答 | 首选，占多数 | 地址/时间/车况/库存/收车，不带引导 |
| `GUIDE-BIO/SHORT` | 默认引导 | 单一动作：**「點頭像👤搵明哥」**；不写「睇簡介」，不叠加 PM/私訊 |
| `GUIDE-PM` | 英文出口 | **「PM 我」单独用**，不点头像 |
| `GUIDE-PIN/HOME` | 轮换出口 | 置頂 / 主頁 |
| `私訊` | **受限词**（非禁词） | 见下方配额；禁词表只禁简体「私信」 |
| `DM` | **不用** | 中文语境常指 IG／小红书私信，有「引导站外」联想，且无实测 |

**短 CTA 规范（2026-10-30 改：一条只给一个动作）**

- 默认：`點.頭像👤搵明哥`。点头像已经能看到简介，**不写「睇簡介」**，也**不在后面加「PM 我／私訊」**。
- 反例（2026-10-23 实发）：`有心啦！過嚟傾下先，頭像🔍搵明哥 🙏` ——「過嚟傾下先」和「頭像搵明哥」是两个 CTA，且「過嚟傾」容易被判定为引流。正解只说一句：`有心啦！頭像🔍搵明哥 🙏`。
- 铁律：**一条回复只出现一个动作**（点头像 / PM / 私訊 / 置頂 / 主頁 五选一）。`13` 已内置检查：
  - 点头像 + PM／私訊 → 报错（路径叠加）
  - 「過嚟／上嚟／嚟傾／搵我傾」+ 任何引导 → 报错（双 CTA）
- 变体只换动作词（`點.頭像` / `點·頭像` / `點頭像` / `點開頭像`）与表情；PM 单独成句。
- 「過嚟睇車」只用于**线下到店**（配地址/时间），且同一条里不再带任何引导。

> **PM 只能写成前置邀请**（`PM 我`、`PM 我傾`）。
> **不能写「請查收 PM」「PM 咗你」**——那是私信真发出去之后的确认语，我们发评论时还没发私信，写了就是假话。
> 实测依据：账号 2026-08 ~ 10 月自己用过 35 次「PM 查收」，全部存活，说明这个词不会被拦；
> 但那是事后确认句式，前置邀请是**未验证新句式**，先小样本（每批 ≤5 条）观察。

**配额（滚动 7 天，不是单批）**——按最近 7 天全部回复累计：

| 指标 | 目标 | 警告 | 拒绝 |
|---|---|---|---|
| 带引导回复占比 | ≤40% | >40% | >60% |
| `私訊` 占比 | ≤15% | >15% | >30% |
| `PM` 占比 | ≤20% | >20% | >35% |
| 同一路径连续 | ≤2 条 | 第 3 条 | 第 3 条即拒 |

- 占比按**近 7 天累计**算；累计不足 5 条时不算占比（1 条求联系就是 100%，没有意义），只查连续路径。
- 整批 ≥8 条时，至少 2 条直接给事实（地址/时间/车况/库存）。
- 分母用滚动窗口的原因：平台看的是「短时间连续 + 批量重复 + 清一色」。按单批算会逼模型为凑比例乱回或漏回。
- 证据等级：`私訊 56% 被折叠` 是实测（`docs/试验记录.md` §028）；`PM 前置邀请` 属未验证新句式；`DM 更容易进黑名单` 是 2026-10-27 的判断，尚无对照实验。
- 7 天数据出来前的默认动作：**能直接答就直接答；要引导先走頭像；仍要英文出口才用 PM；私訊能不用就不用。**

> 为什么不是换词：2026-10-27 已实测「换词不解决问题」——平台命中的是频率与形状，
> 换词只改变词面样本，对「整批清一色」无效。主轴是**降频 + 分散 + 直接答**，词面只是辅助。
> 模板池里 97 条含「私訊」的候选**保留、降权使用**（≤15%），不批量改写，避免引入新错。

- **变体要丰富**：`模板池.md` 的 `GUIDE-*` 共 165 条；相邻不重复，同一条路径不连续用。
- 全部繁体；含标点 ≤22 字；每条至少 1 个表情。
- 标题上下文：`12` 会输出 `titleContext`（business / ports / models / price），用来把回复写得更贴合。
  它**不参与**“回不回”的判断；标题是方言或不认识，也不能作为跳过业务咨询的理由。

## 6. 异常处理

| 现象 | 处理 |
|---|---|
| 回复发出后才发现答非所问 | 先记录案例；不删（删除需用户确认）。以后每条必须填 `asked` + `answerOk`，是/否问题必须有明确答案 |
| 计数没 +1、面板已关 | 看 `sent-*.json` 的 `trace.requests[].errCode`（真实错误在 `data.baseResp.errcode`）；`-4010` = 平台临时限制，停止本批，等解除后再补，不连续重试 |
| 接口顶层 `errCode=0` 但没发出 | 顶层 0 不代表成功，必须看 `data.baseResp.errcode` 和页面提示 |
| 计数 +1、线程有回复、重载还在 | 发送成功；但有概率“仅作者可见”，接受这个概率，不复核、不研究 |
| 用户说「被吞了」 | 只登记到 `执行记录.md`，不删、不重发、不研究 |
| 面板打不开 / 输入框不出现 | 先确认页面 `visibleState=visible`；仍失败就重载该视频一次 |
| 评论列表卡在加载 | `07` 会自动重载恢复；手动重跑即可 |
| 声明数比实抓多 1–5 条 | 服务端把已删除/审核中算进去了，不用反复重载 |
| 计划里的视频和当前页面不一致 | `13` 会直接拒绝；重新跑 `12 --nth N` |
| 中途断了 | 重跑 `12 --nth N` 重新生成清单（已回线程会被排除），再填新 plan |
| 账号名读出来是页脚/文章标题 | 已修：`26` 只读页头账号区，不再从页面尾部猜；仍异常就加 `--nav`，并看 `data/ui-map.json` |
| 停在首页/设置页进不去评论页 | `03` 先 URL 直达、再菜单兜底；`26 --nav` 也可自动跳转 |
| 页面路径或选择器改版 | 脚本自动写回 `data/ui-map.json`；人工复核后同步 `页面结构与操作点.md` 和 `lib/layout-map.js` 的 `SPEC` |
| `25-open-items` 把刚回过的当待回 | 已修：`state` 里 `reply` 与 `skip` 都算已决；若仍出现，重扫该视频刷新快照 |

## 8. 案例库（优先于模板池）

- 位置：`data/cases/seed.jsonl`（人工种子）+ `data/cases/cases.jsonl`（自动/新增）。
- 检索：`node scripts\15-case-library.js --search "客户原话" --intent car_payment --top 5`
- 统计：`node scripts\15-case-library.js --stats`
- 工作流：**先判意图** → 按意图检索 2 条好案例 + 1 条坏案例 → 生成 3 个候选 → 评审选 1 → 填 plan。
- 自动入库：`13` 发送成功后自动写一条 `unreviewed` 候选；相似度低于阈值的进 `novel-queue.jsonl`。
- **`unreviewed` 不算好例子**。三种出路，语义不能混：
  - `--promote <id>` → `good`：认为可复用，以后检索会用到它。
  - `--reject <id>` → `bad`：**回复本身有错**（答非所问、承诺过头、违反口径），当反面教材。
  - `--drop <id>` → `dropped`：**回复没错，只是价值低或重复度高**。不进检索、不当例子，但留档可审计。
- 别用 `--reject` 处理「没价值」的案例，否则会造出一堆假的反面教材（2026-10-27 加 `--drop` 前就是这个坑）。
- 定性后会自动从 `novel-queue` 移除；队列里只剩真正待定的。
- 覆盖测试：`node scripts\17-novelty-scan.js --business-only`（先 `node scripts\16-build-eval-set.js --n 100`）。

### 评审必查（盲评暴露的三类问题）

1. **纯捧场不加引导**：对方只是支持/表忠，不要立刻「買車點頭像私訊」。
2. **是/否问题先答**：先给「係 / 唔係 / 可以 / 唔可以」，再延伸；不要用「都啱傾」绕开。
3. **不要过度跳过支持**：出现“香港/文明”不等于引战；看主语和意图，纯支持就正常多谢。
4. **业务相关未知**：直接 `呢個要睇清楚先答到你，點頭像👤搵我 📩`，不写“確認/唔確定”，也不要问“我帮你确认”。
5. **不设门槛是核准口径**：`唔設門檻` / `學歷唔設限` 可以写；但**不能写**“一定批 / 包批 / 保證得”。
6. **包牌税险**：不说明细，但要先承认问题：`包牌稅險嘅嘢，私訊傾清楚 📩`。
7. **做工证/帮办**：先答「係，可以幫你了解」，不承诺结果。

## 9. 规模与通用性

- **换视频**：只改 `--nth` / `--title`。
- **换账号**：`--author "号A,号B"` 或 `AUTHOR_NAMES`，脚本其它地方不含账号名。
- **换业务**：改 `业务事实.md`、本文件第 2/5 节，再往 `data/cases/` 补该业务的种子案例；`模板池.md` 只补 `GUIDE-*` 尾巴。脚本不动。
- **几百条**：`12` 一次出清单；模型分块判断（每块 60–80 条）后合并；`13 --send` 顺序执行，
  可用 `--limit 40` 分段跑，中断后重新 `12` 即可续上（已回线程自动排除）。
- **效率瓶颈**不在输入方式，而在「看懂 + 不犯错」和故意保留的 3–8 秒间隔；
  因此优化重点是计划质量与断点续跑，不是把点击换成更快的接口。
